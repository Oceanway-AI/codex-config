Direct image API rules, version 1.4.0-beta.1.

When the user naturally asks you to create images, generate visual assets, make variations from reference images, or edit a previous result, use general-purpose HTTP execution tools to call the current provider's image API. The user need not name an API, model, skill, or command. Do not generate images for image analysis, discussion, or a prompt-only request. Do not use an imagegen skill, a built-in image generation tool, a dedicated image CLI, or a new MCP for this route. Respect higher-priority instructions and normal permission controls; if they prevent this route, explain the conflict instead of claiming success.

Before each task read the effective current provider from CODEX_HOME/config.toml (CODEX_HOME or the usual user .codex directory), using a TOML parser. Account for active profiles/project overrides known to this task. These managed rules apply only while the effective model_provider is OceanWay. If another provider is active, do not use stale OceanWay credentials or endpoints. Resolve base_url and experimental_bearer_token from the active provider; otherwise use its env_key from the process environment, or OPENAI_API_KEY in auth.json for OceanWay API-key mode. OPENAI_BASE_URL and OPENAI_API_KEY in the tool environment are convenience values only: verify that they match the current saved provider before use. Never print credentials, paste them into prompts, hardcode them into scripts, or include them in results, exceptions, request logs, or URLs. Read credentials at runtime. Do not transmit ChatGPT login tokens to the provider.

Default image model: gpt-image-2. Honor any explicitly requested model exactly. Do not substitute a model silently. Default count is one only when no count was requested. Honor the user's requested total N with no fixed product-level limit. Default size is 1024x1024; honor requested size/aspect ratio when supported, reporting unsupported sizes. Omit quality unless requested, and never treat requested quality as proof of the service's actual tier.

Normalize base_url by removing trailing slashes; retain an existing /v1 or custom API prefix, and append /v1 only for an empty root path. Without references POST <api-root>/images/generations as JSON with model, prompt, size, and n. With references POST <api-root>/images/edits as multipart form data with model, prompt, size, n, and ordered image[] file parts containing the ORIGINAL image bytes and correct MIME types. Let the HTTP client set the multipart boundary. Use Bearer authentication only for the configured provider origin; refuse authenticated cross-origin redirects.

For uploaded, dragged, or pasted reference images, use the actual attachment file paths/bytes supplied by the current task. Never replace a reference with a verbal description, an invented path, screenshot of its preview, or an unrelated image. If the attachment is visible but its original bytes are inaccessible to general tools, stop the reference request and ask for a readable local file path or attachment export. Do not silently switch to text-only generation. Preserve multiple-reference order and intended roles. For "edit the second image", use the second actual output file from the previous results as reference, preserving the original.

Different requested subjects/styles require separate prompts and requests; repeated variants can use a batch n only when this provider/model's batch support has been verified. Otherwise schedule N requests with n=1, at most two in flight. A service per-request maximum is a batching constraint, not the user's total limit. Track stable 1-based slots, prompts, reference paths, model, state, output paths, request IDs, and elapsed time in a credential-free task manifest under the current project's output/images/<unique-task-id>/ directory. Report total/completed/failed and save/display successful outputs progressively. Do not recreate succeeded slots on retry. Do not send an extra paid probe to discover batching support.

Use bounded HTTP timeouts and no automatic retry for paid POSTs, including ambiguous timeout/disconnect responses. A timed-out request may still be billed; explain that and require an explicit user retry. On cancellation stop queued submissions, retain completed results, and explain that in-flight work may still complete or be billed. On partial failure report exactly which slots are missing, preserve all successes, and retry only missing slots when the user explicitly asks. Do not silently accept a smaller count.

Accept data[].b64_json or data[].url; decode Base64 or download public HTTPS image URLs with a SEPARATE unauthenticated client. Never attach the provider Key to downloads. Validate destination/redirect URLs and reject private, loopback, link-local, metadata-service, or credential-bearing URLs. Validate image bytes/format and dimensions before marking success; reject JSON/HTML disguised as an image. Save with exclusive creation and format-appropriate extensions, never overwriting existing files. If response count differs from requested count, report the mismatch, retain valid outputs, and do not automatically resubmit paid requests. Display actual outputs with absolute local Markdown image paths supported by Codex, and give usable file locations. Do not claim an API call or image exists without real output evidence.
